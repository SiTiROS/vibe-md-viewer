# Сборка, тесты, замеры

[English](BUILD.md) | **Русский**

## Что нужно

- Rust stable с целевой платформой `x86_64-pc-windows-msvc` (rustup).
- Visual Studio 2022 Build Tools / Community с компонентом «Разработка классических приложений на C++» (нужны `link.exe`, `rc.exe`, Windows SDK).
- Больше ничего: ни Node.js, ни .NET, ни WebView2.

## Правило: ничего не класть на диск C:

Инструменты по умолчанию складывают кеши в профиль пользователя. Скрипт `scripts\env.ps1` перенаправляет всё внутрь проекта:

| Переменная | Куда |
| --- | --- |
| `CARGO_HOME` | `.toolcache\cargo` — реестр и исходники крейтов |
| `CARGO_TARGET_DIR` | `target\` |
| `TEMP`, `TMP` | `.toolcache\tmp` — временные файлы компилятора и линковщика |

Сам тулчейн Rust (уже установленный в профиле) только используется, туда ничего не докачивается. Любые команды `cargo` запускайте после `. .\scripts\env.ps1`.

Скрипты `.ps1` сохранены в UTF-8 **с BOM** — иначе Windows PowerShell 5.1 ломается на кириллице.

## Команды

```powershell
# релиз → dist\vibe-md-viewer.exe (≈2.7 МБ)
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
# то же + тесты
powershell -ExecutionPolicy Bypass -File scripts\build.ps1 -Test

# разработка
. .\scripts\env.ps1
cargo build           # target\debug\vibe-md-viewer.exe
cargo test            # юнит-тесты

# сквозной самотест на живом окне (окно мелькнёт на секунду)
powershell -ExecutionPolicy Bypass -File scripts\selftest.ps1

# замер скорости открытия
powershell -ExecutionPolicy Bypass -File scripts\bench.ps1 [-File путь.md] [-Runs 15]
# большой документ (~270 КБ): тема, режимы, ширина, масштаб, время кадра прокрутки
powershell -ExecutionPolicy Bypass -File scripts\profile.ps1 [-Size 2560x1380]

# пакет для раздачи: сборка + тесты → dist\vibe-md-viewer-<версия>-setup.exe, .zip (+ .sha256.txt, лицензии)
powershell -ExecutionPolicy Bypass -File scripts\package.ps1

# реальная загрузка картинки из интернета (сеть!)
cargo test --release fetch_public -- --ignored

# перерисовать иконку assets\app.ico
powershell -ExecutionPolicy Bypass -File scripts\make-icon.ps1
```

## Выпуск новой версии

1. Поднять `version` в `Cargo.toml` (единственное место: версия попадает в свойства exe через `build.rs` и в логику обновления).
2. Дописать раздел `## X.Y.Z — дата` в `CHANGELOG.md` (английский — он станет описанием релиза) и в `CHANGELOG.ru.md`.
3. Закоммитить и отправить в `main`. Тег ставить не нужно.
4. Релиз выходит автоматически. Когда CI на `main` проходит, GitHub Actions (`.github/workflows/release.yml`) проверяет, есть ли уже релиз версии из `Cargo.toml`. Если нет, то:
   - собирает и тестирует именно этот коммит (`scripts\package.ps1`, самотест);
   - подписывает происхождение сборки;
   - публикует релиз `vX.Y.Z` (тег создаётся на этом коммите) с `vibe-md-viewer-X.Y.Z-setup.exe`, zip, контрольными суммами и `THIRD-PARTY-NOTICES.txt`.

   Коммиты без смены версии релизов не создают. Запустить вручную: Actions → Release → Run workflow.

Локально то же самое — `scripts\package.ps1` → `dist\`.

## CI

`.github/workflows/ci.yml` — на каждый push в `main` и pull request, раннер `windows-latest`: `cargo test --release --locked` (включая тесты на настоящем RichEdit), `cargo build --release --locked`, самотест на живом окне (`scripts\selftest.ps1`), exe — артефактом сборки на 14 дней. Только официальные действия `actions/*`, права токена — только чтение. В CI кеши cargo — стандартные (правило «ничего на C:» касается машины разработчика: там всегда `. .\scripts\env.ps1`).

Пользователь обновляется запуском нового exe (см. README, «Обновление»). Сравнение версий — числовое `a.b.c`: обновление предлагается только если новая версия больше установленной.

## Покрытие кода тестами

`scripts\coverage.ps1` собирает программу со счётчиками покрытия (`-C instrument-coverage`, в `target\cov`), прогоняет юнит-тесты, самотест на живом окне и служебные режимы (`--profile` на большом документе, снимки, время запуска, окно установщика — ничего не устанавливается) и печатает покрытие строк по файлам; `-Html` дополнительно пишет HTML-отчёт в `.toolcache\coverage\html`, `-MinLines N` падает, если покрытие ниже N%.

Нужны `llvm-profdata.exe` и `llvm-cov.exe` той же версии LLVM, что у `rustc` (`rustc -vV`). В CI они берутся из компонента rustup `llvm-tools`. Локально, чтобы ничего не ставить на диск C:, они кладутся в `.toolcache\llvm-tools`: архив `llvm-tools-<версия>-x86_64-pc-windows-msvc.tar.xz` для вашей версии `rustc` — по манифесту `https://static.rust-lang.org/dist/channel-rust-<версия>.toml`, из него достаются только эти два файла.

Сейчас покрытие строк — **87,7%**. Основные модули покрыты на 96–100%: render, html, highlight, styler, editor, richedit, links, images, doc, settings, theme, emoji.

Что не покрыто и почему:
- модальные окна и системные диалоги (вопросы, открытие/сохранение файла, UAC): `dialogs.rs` — 0%, окно установщика — 56%;
- установка в Program Files и HKLM с правами администратора (`install.rs` — 72%);
- настоящая загрузка из интернета;
- ветки на случай отказа вызовов Win32.

Всё остальное покрыто юнит-тестами или самотестом. 100% недостижимы без человека, который проходит UAC и диалоги.

Задача CI `coverage` запускает тот же скрипт с `-MinLines 85` и показывает сводку на странице прогона; HTML-отчёт — артефактом.

## Ключи командной строки

| Ключ | Назначение |
| --- | --- |
| `файл.md` | открыть файл |
| `--mode view\|visual\|code` | режим при запуске (`visual` используется пунктом «Редактировать» в проводнике) |
| `--install`, `--uninstall` | установка / удаление (с диалогами) |
| `--setup` | окно мастера установки (так же — если в имени exe есть «setup») |
| `--register` | перерегистрировать текущий exe для `.md` без копирования |
| `--timing ФАЙЛ` | дописать в файл время до первой отрисовки и разбивку по этапам |
| `--exit-after-paint` | выйти сразу после первой отрисовки (для замеров) |
| `--snapshot PNG` | дождаться картинок, сохранить снимок окна и выйти |
| `--size ШxВ`, `--scroll Y` | размер окна и прокрутка для снимка |
| `--selftest` | сквозной самотест на открытом файле (лог `<имя>.selftest.log`), код возврата 0/3 |
| `--profile ФАЙЛ` | замер на реальном окне: открытие (до показа / фоновая догрузка), прокрутка, смена темы, ширины, масштаба, режимов; проверка, что место чтения сохраняется |

## Замер скорости

Время считается от создания процесса до полностью нарисованного окна с документом (картинки догружаются после). Машина разработчика, release-сборка, медиана 15 запусков:

| Документ | До первой отрисовки |
| --- | --- |
| `tests\fixtures\showcase.md` (все виды разметки, 2 картинки), окно 1100×860 (`--size 1100x860`) | ≈ 80 мс |
| то же, окно по умолчанию (85% экрана) — `scripts\bench.ps1` | ≈ 88 мс (экран 2560×1440, 0.1.3) |
| `docs\ARCHITECTURE.ru.md` (≈ 8 КБ, много таблиц) | ≈ 100 мс |

Время отрисовки растёт с площадью окна: большое окно по умолчанию (с 0.1.1) добавляет ≈ 20 мс. Подсветка синтаксиса на скорость не влияет (0.1.0 и 0.1.1 при одинаковом окне — 81,9 и 81,5 мс).

Разбивка (мс от старта процесса): до `main` ≈ 10, окно и панели ≈ 10, создание RichEdit ≈ 12, разбор и загрузка документа ≈ 14, показ и отрисовка ≈ 30.

Прокрутка (`scripts\profile.ps1 -Size 2560x1380`, документ 268 КБ): кадр в среднем 2,6 мс, 95% кадров — до 3,6 мс, худший ≈ 6 мс; бюджет кадра при 144 Гц — 6,9 мс.

Что уже сделано для скорости:

- редкие DLL (WinHTTP, shell32, comdlg32, ole32, oleaut32; d2d1 и dwrite для цветных эмодзи — только после первой отрисовки документа с эмодзи) загружаются отложенно (`/DELAYLOAD`, см. `build.rs`);
- редактор исходника создаётся только при первом переходе в режим правки;
- потоки декодирования картинок создаются лениво;
- статический CRT, LTO, `codegen-units = 1`.

```
src/                исходники (см. docs/ARCHITECTURE.md)
assets/             иконка, манифест, ресурсы, стартовая страница welcome.en.md / welcome.ru.md, README.txt / ПРОЧТИ.txt для zip
scripts/            env / build / bench / selftest / profile / package / notices / make-icon

.claude/memory/     память ассистента (junction из профиля; не в git)
```
