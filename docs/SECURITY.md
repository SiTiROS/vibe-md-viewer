# Security

**English** | [Русский](SECURITY.ru.md)

A `.md` file is untrusted data: a README from an archive, documentation from the internet, an email attachment. The program assumes that any opened file may be hostile.

## What research of existing apps showed

Almost all notable vulnerabilities of Markdown apps in recent years come from one of three decisions: **a browser engine for rendering**, **“smart” links that pass the address to the system as is**, **automatic loading of resources**.

| App | Vulnerability | Root cause |
| --- | --- | --- |
| Windows 11 Notepad | CVE-2026-20841 (CVSS 8.8): clicking a link in Markdown launched an unchecked protocol handler → code execution | links passed to the system without a protocol allow list |
| Typora | CVE-2023-2317: DOM-XSS → code execution (Electron); CVE-2024-41481/41482 — via Mermaid and MathJax | browser engine + scripts |
| MarkText | CVE-2023-2318 (DOM-XSS), CVE-2021-29996 (mXSS → RCE) | browser engine |
| Obsidian | CVE-2023-2110: reading local files | browser engine |
| Joplin | CVE-2026-49449: link allow-list bypass via KaTeX → a `\\server` path → NTLMv2 leak | network paths |
| Mattermost Desktop | CVE-2026-6517: a Markdown image from the attacker's server → NTLM leak | automatic resource loading + network paths |
| SiYuan | CVE-2026-40107: a Mermaid image with a `//host` address → UNC → NTLM leak without a click | automatic resource loading |
| Markdown Preview Enhanced (VS Code) | CVE-2026-49492: opening links through the shell without checks → RCE | links without an allow list |
| comrak (Rust parser) | CVE-2023-28626: quadratic complexity → hang | parser DoS |
| RichEdit/WordPad | KB5032314: OLE objects in RTF → NTLM leak; MS07-013: OLE in RTF → memory corruption | untrusted RTF/OLE |

Native viewers without a browser exist (Inlyne on wgpu, mdmdview on egui, Velotype on GPUI), but none combines fast startup, visual editing and registration as the `.md` app on Windows, so this one was written.

## Threat model

The attacker controls the contents of the `.md` file (and possibly neighbouring files in the same folder). The attacker's goals:

1. execute code (scripts, protocols, executables, memory corruption in parsers/decoders);
2. steal the Windows password hash (NTLM) through access to `\\server`;
3. learn that the document was opened (IP, time) — a “tracking pixel”;
4. deceive the user (a link shows one address and leads to another);
5. hang or crash the program (DoS).

## Measures

### No engine that can execute code

- Rendering is RichEdit (formatted text), not a browser. HTML inside `.md` is **never executed**: only the formatting meaning is taken from tags (`<b>`, `<img src>`, `<a href>`, `align`). The contents of `<script>`, `<style>`, `<iframe>`, `<object>`, `<svg>`, `<form>` etc. are not shown at all. Handler attributes (`onerror=`…) are ignored — there is simply nothing to run them.
- **RichEdit only receives RTF generated by the program** (`render.rs`). Chunked loading (`Rendered::chunk_rtf` → `richedit::insert_rtf`) cuts this same RTF only at top-level boundaries where all groups are closed — chunks can't “break” the escaping. All document text is escaped: `\`, `{`, `}` and all non-ASCII → `\uN?`. Injecting RTF control words (`\object`, `\field`, `\objupdate`) is impossible — a test checks it.
- **Document text in the editor is always plain text.** `EM_SETTEXTEX`/`EM_REPLACESEL` treat text starting with `{\rtf` as RTF (confirmed by the self-test: an earlier version did exactly that), so text is set and inserted only through TOM `ITextRange::SetText`.
- Clipboard: **paste plain text only** (Ctrl+V, Shift+Insert, `WM_PASTE` are intercepted), copy only `CF_UNICODETEXT`. RTF and OLE objects from the clipboard never reach the control. OLE drag-and-drop is off (`ES_NOOLEDRAGDROP`, `RevokeDragDrop`). Conversion of linked OLE objects is off (`EM_SETDISABLEOLELINKCONVERSION`, KB5032314).
- RichEdit URL auto-detection is off: links are controlled only by our policy.

### Link allow list (`links.rs`)

| Link | Action |
| --- | --- |
| `#section` | scroll to the heading |
| `http://`, `https://` | default browser; the address is normalized |
| `mailto:` | mail app |
| a local `.md` | opens in the same window |
| another local file | checked **at click time** by the real long name (`GetLongPathNameW`: `X~1.LIB` → `x.library-ms`), no symbolic links in the path; only an **allow list** of types can be opened (after confirmation) — images, PDF, text, docx/xlsx/pptx/odt, media; everything else and folders — only “Show in Explorer” |
| `.exe .bat .cmd .lnk .ps1 .vbs .js .hta .msi .reg .scr .url .theme .appinstaller …` (≈90 types) | **blocked** |
| `javascript: vbscript: data: file://server ms-msdt: search-ms: ms-officecmd: shell:` and any other protocol | **blocked** |
| `\\server\...`, `//server/...`, `\\?\`, `\\.\`, a path through a symbolic link | **blocked** (NTLM leak, devices) |
| `CON`, `NUL`, `COM1`…, `COM¹`…, `file.md:stream`, `setup.exe.`, `setup.exe%20` | **blocked** (devices, NTFS streams, extension masking with a trailing dot/space) |
| an address with hidden control, bidi or zero-width characters | **blocked** (Trojan Source, CVE-2021-42574) |

Also:

- **The real address is visible before the click** in the status bar, with an icon: `↗` web, `📄` document, `📁 (will ask)`, `⛔ blocked`.
- Blocked links are visible in the text right away: a warning color and a dotted underline.
- A warning before opening if the link text shows one site but leads to another (`[https://bank.com](https://evil.com)`, “Sign in to bank.com”; invisible characters and look-alike dots `．` `。` are removed before comparing), if the address has `user@` before the host (`https://bank.com@evil.com`), or if the host contains non-Latin letters. In the editor (Ctrl+click) the visible link text is compared.
- `mailto:` — only the address and `subject`/`body`/`cc`/`bcc` (no `attach=`), special characters are encoded, `&` in the address is encoded.
- An unclosed `<a href>` is closed at the paragraph boundary (it doesn't turn the document into one invisible link).
- Internal `vmd:` links (install/uninstall) work only on the built-in start page — a document can't trigger them.

### Images (`images.rs`, `net.rs`)

- The same path rules as for links: no `\\server`, devices or streams; only image extensions are accepted.
- `data:` — only raster `image/*` in base64: up to 8 MB per image and 32 MB per document.
- **Decoding only with safe Rust decoders** (`png`, `zune-jpeg`, `gif`, `image-webp`, `bmp`, `ico`) with limits: up to 16384×16384 pixels, up to 256 MB of memory per image, a local file up to 60 MB. A decoder error or panic is caught in the worker thread and doesn't crash the program.
- `width`/`height` from the document are limited (≤ 10000); pixels are only ever reduced on each side when re-encoding, the result is ≤ 16 Mpix (previously `height="4000000000"` caused a terabyte allocation and an abort). The intermediate buffer of scaling is limited too: a large one-sided shrink uses integer averaging instead.
- Identical images load as one job; jobs from previous renders are cancelled.
- RichEdit receives a PNG/JPEG **re-encoded by us**, scaled to the column width. Windows system codecs (WIC) never parse untrusted bytes.
- SVG is not supported (it's XML with its own attack surface).
- **Images from the internet — only with permission**: by default a bar “Load / Always load” appears. The setting `remote_images = ask | always | never` in `settings.ini`.
- Loading via WinHTTP: http/https only, **no automatic sending of Windows credentials** (`AUTOLOGON_SECURITY_LEVEL_HIGH`), cookies off, no Referer, 25 MB, timeouts and a 30 s total limit per image.
- Local network addresses are forbidden: `localhost`, `10.x`, `192.168.x`, `169.254.x`, `100.64/10`, `fc00::/7`, `fe80::/10`, `fec0::/10`, IPv4 inside IPv6 (`::ffff:`, `::ffff:0:`, `::a.b.c.d`, 6to4 `2002::`, NAT64), single-label names, `.local`, `.lan`…; non-canonical IP notations (`127.1`, `2130706433`, `0x7f.0.0.1`, `0177.0.0.1`) are forbidden; the host name is resolved via DNS in advance and checked; **automatic redirects are off** — every redirect is checked again (a public address can't redirect to your router), https→http is forbidden, at most 5 steps.

### Process and build

- `SetDefaultDllDirectories(SYSTEM32)` and `SetDllDirectory("")`: DLLs are looked up only in System32, the current folder is excluded. Planting `msftedit.dll` next to a `.md` is useless.
- The `ProcessImageLoadPolicy` process policy: no DLLs from network paths or with a low integrity label, System32 preferred.
- **DLL planting next to the exe is closed.** Only KnownDLLs (kernel32, user32, gdi32, advapi32, combase) and API sets are imported statically. `uxtheme`, `dwmapi`, `bcryptprimitives` (not KnownDLLs — Windows would look for them in the exe folder first, before our code starts) and WinHTTP/shell32/comdlg32/ole32/oleaut32/ws2_32 are delay-loaded — after `SetDefaultDllDirectories(SYSTEM32)`, only from System32. Important for the installer started from “Downloads” with administrator rights. Check: `dumpbin /imports dist\vibe-md-viewer.exe`.
- Built with Control Flow Guard, ASLR/DEP (the Rust/MSVC defaults), static CRT.
- The `asInvoker` manifest: the viewer always runs with normal rights. Only the installer copy (`--elevated …`) gets administrator rights (UAC), for the duration of install/update/uninstall; the default-app window and starting the program after an update happen from the normal process.
- **An all-users installation goes only into `C:\Program Files\vibe-md-viewer`** (`FOLDERID_ProgramFiles`; the elevated copy rejects any other `--target`). All folders above it belong to administrators: a regular user can't swap the folder or the path to it (by renaming the parent, with a junction). A custom folder is allowed only for a just-for-me installation, without administrator rights. On behalf of an administrator, folders are deleted only directly inside Program Files.
- **The installer copies the running image itself, not a file by path.** A running exe can be renamed: a program with user rights could, while the elevated copy waits for UAC, put its own file named setup.exe into “Downloads”. The elevated copy finds the file through the image mapping (`K32GetMappedFileNameW`), opens it denying write and delete to others, and verifies the file ID (`open_own_image`, test `own_image_is_opened_by_mapping`).
- An installation folder path containing `..` or `.` is rejected.
- The all-users installation folder gets protected rights like Program Files (only SYSTEM and administrators can modify it, owner — administrators); someone else's non-empty folder is never taken for installation; the path is checked (name `vibe-md-viewer`, not in `%SystemRoot%`, no `" % !`). Uninstall deletes only a folder with the installer marker; `cmd /d /v:off`, `PING.EXE` by full path, current folder — System32.
- **Moving a 0.1.x installation (vibe-mdViewer → vibe-md-viewer, 0.2.0)** deletes the old folder on behalf of the elevated copy. The path comes not from the command line but from `InstallDir` in the same registry scope (for all users — HKLM, writable only by administrators); it's deleted only if the folder name is `vibe-mdViewer`, the path passes the same shape checks, it's directly inside Program Files, and it contains the installer marker and the program's exe (`may_delete`, test `legacy_install_is_recognized_and_moved`). A different name or a folder without the marker is never touched.
- Every window procedure is wrapped in `catch_unwind`: an unexpected error doesn't kill the process and doesn't unwind through user32 frames. Document parsing and highlighting are guarded too (on failure the document is shown as text).
- Aggressive mitigations (no dynamic code, no extension points) are deliberately not enabled: they break third-party shell extensions in the open-file dialogs and keyboard layout switchers.

### Denial of service

- Files larger than 64 MB are not opened.
- pulldown-cmark is linear on pathological inputs; **so is the program's own code**: bare URL search, the HTML tokenizer (tag ≤ 4 KB, the `>` position is remembered), entity decoding (`;` is searched in the first 32 bytes), RTF groups (a counter instead of rescanning, depth ≤ 48, HTML groups ≤ 256).
- Links/anchors/images with markers — up to 2048/1024/2048; addresses longer than 8 KB are not copied or parsed (a megabyte `[x]: …` definition referenced thousands of times is not multiplied in memory).
- Tables: ≤ 60 columns (RichEdit's limit is 63), ≤ 60,000 cells per document (then “table truncated”); the whole RTF ≤ 96 MB, beyond that a message suggests the Code mode.
- Images are decoded in background threads — a large file doesn't freeze the window.
- Syntax highlighting (`highlight.rs`): one pass without regular expressions or backtracking; an unclosed string/comment extends to the end of the line or block; a block larger than 256 KB is not highlighted; closing brackets of `#[` / `${` are searched only within the line. Colors are only indices into our color table; code text is escaped like everything else (test `covers_everything_and_is_linear`: 10,000 unclosed strings, 85,000 unclosed `#[`, etc.).
- The test `pathological_inputs_are_fast_and_balanced` runs ≈25 “bombs” (60,000 brackets, 300,000 `<b>`, 1,000,000 `&`, `<a <a <a…`, megabyte link definitions, 100 MB `data:`, a 60×6000 table…): all ≤ 1 s, RTF balanced, memory bounded.

### Saving

- Autosave writes **only to the opened file** (same path, same atomic write), only if the editor text differs from the saved one; the start page and files without a path are never saved. A write error is not retried in a loop — a message in the status bar. Turned off with `autosave=0`.
- Autosave never overwrites changes made by another program: if the file changed on disk while there are unsaved edits, autosave stops and Ctrl+S asks before overwriting. A file read with replaced broken characters (invalid UTF-8/UTF-16, NUL) is not saved automatically.
- Atomic write: a temporary file with a unique name (`create_new` — a planted file or symbolic link is never overwritten) → `ReplaceFileW` (keeps attributes and permissions) → on failure the original is intact.
- Encoding and line endings are kept as in the original file. If characters outside the code page are added to an ANSI file, it's saved as UTF-8 with a message.

## Known limitations

- A running copy trusts local files referenced by the document: they are **shown** (images) or opened **after confirmation**. No information is sent anywhere — the program has no document-executed code that could exfiltrate it.
- Paths with symbolic links are rejected on click and when loading an image. Junctions are allowed — they only lead to local volumes.
- If the user allowed images from the internet, their servers learn the IP and the time of opening — the bar warns about it.
- **DNS rebinding** (only after allowing images from the internet): the name is checked in advance, but WinHTTP resolves it again; a server with TTL=0 could in theory return a local network address the second time and receive a “blind” GET request. Closing it fully requires checking the IP at connect time, which breaks corporate proxies; the risk is low and accepted deliberately.
- The exe is not code-signed: SmartScreen warns about an unknown publisher. Signing needs a paid certificate or a free program for open-source projects (e.g. SignPath Foundation) — the owner's decision. The authenticity of a release can be verified with the GitHub build provenance attestation: `gh attestation verify <file> -R SiTiROS/vibe-md-viewer`.
- “Show in Explorer” opens the folder the document points to (after confirmation). If it contains a `desktop.ini` with an icon on a network path, Explorer may contact that server — this is Explorer's behaviour, not the program's.
- A 0.1.x all-users installation in a custom folder is not deleted when moving to 0.2.0 (on behalf of an administrator only folders in Program Files are deleted) — it can be removed manually.

## Independent audit (2026-11-18)

The code was reviewed by a separate reviewer from scratch (static reading, without knowing the author's conclusions). All confirmed findings are fixed and covered by tests:

| Finding | Severity | Status |
| --- | --- | --- |
| 8.3 short names (`X~1.LIB`) bypassed the dangerous-type block | high | fixed: long name + allow list |
| RTF injection in the editor through a document starting with `{\rtf` | high | fixed: TOM `SetText` (found by the author, confirmed by the self-test) |
| DLL planting next to the exe (uxtheme/dwmapi/bcryptprimitives) | high for the installer | fixed: delay loading |
| `<img width=100 height=4000000000>` → terabyte allocation, abort | medium | fixed |
| Memory/CPU explosion via megabyte link definitions, `data:`, tables | medium | fixed: limits and budgets |
| Quadratic algorithms (addresses+brackets, `<a <a`, `&&&`, `<b>`×10⁶) | medium | fixed: linear versions |
| Installation folder rights on a non-system drive, `ping` looked up in the current folder | medium | fixed: Program Files + protected rights, full path |
| Crash on Ctrl+click next to a no-break space | low | fixed |
| Spoofing check bypass (invisible characters, `．`), Ctrl+click without text, unclosed `<a href>` | low | fixed |
| Out of bounds in the toolbar after the button set changed | low | fixed |
| Endless error dialogs for a modified unreadable file | low | fixed |
| Unclosed `<form>`/`<template>` hid the rest of the document | low | fixed |
| `[::127.0.0.1]`, 6to4, slow server, OLE drag-and-drop | hypotheses | fixed preventively |
| DNS rebinding for images from the internet | low | accepted (see limitations) |

## Independent audit 0.2.0 (before publishing the source)

A second independent reviewer, static reading. No code execution from a document and no RTF injection were found; the findings are in the installer and in edge cases. All are fixed, each with a test:

| Finding | Severity | Status |
| --- | --- | --- |
| All-users installation into a custom folder: the parent folder is writable by a regular user → exe swap for all users, redirected deletion on behalf of an administrator | medium–high | fixed: Program Files only; elevated deletion only there |
| The elevated copy copied the exe by path from “Downloads” — the file could be swapped while waiting for UAC | medium | fixed: copying the image itself by handle, with verification |
| `<img width=1 height=10000>` on a 16384×16000 image: the scaling intermediate buffer ≈ 2.6 GB → abort | medium | fixed: buffer limit, otherwise a “thumbnail” |
| Highlighting: thousands of unclosed `#[` / `${` — quadratic time, the window hangs | low | fixed: the closing bracket is searched only within the line |
| Autosave overwrote changes made by another program (git pull) and files read with replaced broken characters | low (data loss) | fixed: autosave stops, Ctrl+S asks |
| GitHub Actions: token in `.git`, write permission for the whole build job, actions by tag, build without `--locked` | low | fixed: `persist-credentials: false`, build and publish are separate jobs, pinned SHAs, `--locked`, build provenance |
| An installation path with `..` passed validation | low | fixed |
| The fallback text insertion into RichEdit didn't recognize all RTF signatures | low | fixed: any text starting with `{` |
| A folder name with a backtick could add markup to the start page | informational | fixed: the path is always inside a code span |
| Gaps in the lists: invisible U+200B–200D, U+2028/2029, U+2060–2064, tags, variation selectors; `COM¹`–`LPT³`; `&` in a `mailto:` address; `::ffff:0:a.b.c.d`, `fec0::/10` | informational | fixed |

## Reporting a vulnerability

Privately, via **Security → Report a vulnerability** in the GitHub repository (not in public issues). Please include the version, steps, and if possible a sample `.md`. A fix is released as a separate version with a CHANGELOG entry.

## How to verify

- `cargo test` — unit tests of the link policy (javascript, protocols, UNC, devices, streams, executables, 8.3, trailing dots, bidi, spoofing), images (huge sizes, one-sided shrink), network (private addresses, redirects), RTF escaping, PUA, HTML, “bombs”, the installer (registry on a temporary branch, updating over a “running” exe, legacy migration, copying the own image).
- `tests/fixtures/attack.md` — a set of attacks for manual checking: no link must work, no network image must load.
- `scripts/selftest.ps1` — an end-to-end check on a live window (43 checks, including RTF injection, the find dialog, autosave when another program changed the file).
