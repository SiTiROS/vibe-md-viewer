# Безопасность

[English](SECURITY.md) | **Русский**

`.md` — это недоверенные данные: README из архива, документация из интернета, вложение из почты. Программа исходит из того, что любой открытый файл может быть враждебным.

## Что показало исследование готовых программ

Почти все громкие уязвимости markdown-программ последних лет — следствие одного из трёх решений: **браузерный движок для отрисовки**, **«умные» ссылки, передающие адрес системе как есть**, **автоматическая загрузка ресурсов**.

| Программа | Уязвимость | Корень |
| --- | --- | --- |
| Блокнот Windows 11 | CVE-2026-20841 (CVSS 8.8): клик по ссылке в markdown запускал непроверенный обработчик протокола → выполнение кода | ссылки отдаются системе без белого списка протоколов |
| Typora | CVE-2023-2317: DOM-XSS → выполнение кода (Electron); CVE-2024-41481/41482 — через Mermaid и MathJax | браузерный движок + скрипты |
| MarkText | CVE-2023-2318 (DOM-XSS), CVE-2021-29996 (mXSS → RCE) | браузерный движок |
| Obsidian | CVE-2023-2110: чтение локальных файлов | браузерный движок |
| Joplin | CVE-2026-49449: обход белого списка ссылок через KaTeX → путь `\\сервер` → утечка NTLMv2 | сетевые пути |
| Mattermost Desktop | CVE-2026-6517: markdown-картинка со своего сервера → утечка NTLM | автозагрузка ресурсов + сетевые пути |
| SiYuan | CVE-2026-40107: Mermaid-картинка с адресом `//хост` → UNC → утечка NTLM без клика | автозагрузка ресурсов |
| Markdown Preview Enhanced (VS Code) | CVE-2026-49492: открытие ссылок через оболочку без проверки → RCE | ссылки без белого списка |
| comrak (Rust-парсер) | CVE-2023-28626: квадратичная сложность → зависание | DoS парсера |
| RichEdit/WordPad | KB5032314: OLE-объекты в RTF → утечка NTLM; MS07-013: OLE в RTF → порча памяти | недоверенный RTF/OLE |

Готовые нативные просмотрщики без браузера тоже есть (Inlyne на wgpu, mdmdview на egui, Velotype на GPUI), но ни один не сочетает быстрый старт, визуальную правку и регистрацию как программы для `.md` в Windows, поэтому сделан свой.

## Модель угроз

Злоумышленник контролирует содержимое `.md` (и, возможно, соседние файлы в той же папке). Цели атакующего:

1. выполнить код (скрипты, протоколы, исполняемые файлы, порча памяти парсеров/декодеров);
2. украсть хеш пароля Windows (NTLM) через обращение к `\\сервер`;
3. узнать, что документ открыт (IP, время) — «пиксель слежения»;
4. обмануть пользователя (ссылка показывает один адрес, ведёт на другой);
5. подвесить или уронить программу (DoS).

## Меры

### Нет движка, способного выполнить код

- Отрисовка — RichEdit (форматированный текст), а не браузер. HTML внутри `.md` **никогда не выполняется**: из тегов берётся только смысл для оформления (`<b>`, `<img src>`, `<a href>`, `align`). Содержимое `<script>`, `<style>`, `<iframe>`, `<object>`, `<svg>`, `<form>` и т. п. не показывается вовсе. Атрибуты-обработчики (`onerror=`…) игнорируются — их просто некому исполнить.
- **В RichEdit попадает только RTF, сгенерированный программой** (`render.rs`). Загрузка по частям (`Rendered::chunk_rtf` → `richedit::insert_rtf`) режет этот же RTF только на границах верхнего уровня, где все группы закрыты, — части не могут «разорвать» экранирование. Весь текст документа экранируется: `\`, `{`, `}` и всё не-ASCII → `\uN?`. Внедрить управляющие слова RTF (`\object`, `\field`, `\objupdate`) невозможно — это проверяется тестом.
- **Текст документа в редакторе — всегда простой текст.** `EM_SETTEXTEX`/`EM_REPLACESEL` распознают текст, начинающийся с `{\rtf`, как RTF (проверено самотестом: прежняя версия так и делала), поэтому текст ставится и вставляется только через TOM `ITextRange::SetText`.
- Буфер обмена: **вставка только чистого текста** (перехвачены Ctrl+V, Shift+Insert, `WM_PASTE`), копирование — только `CF_UNICODETEXT`. RTF и OLE-объекты из буфера в контрол не попадают. OLE drag-and-drop выключен (`ES_NOOLEDRAGDROP`, `RevokeDragDrop`). Конвертация связанных OLE-объектов выключена (`EM_SETDISABLEOLELINKCONVERSION`, KB5032314).
- Автоопределение URL в RichEdit выключено: ссылками управляет только наша политика.

### Белый список ссылок (`links.rs`)

| Ссылка | Действие |
| --- | --- |
| `#раздел` | прокрутка к заголовку |
| `http://`, `https://` | браузер по умолчанию; адрес нормализуется |
| `mailto:` | почтовая программа |
| локальный `.md` | открывается в этом же окне |
| другой локальный файл | проверка **в момент клика** по настоящему длинному имени (`GetLongPathNameW`: `X~1.LIB` → `x.library-ms`), без символических ссылок в пути; открыть (после подтверждения) можно только **белый список** типов — картинки, PDF, текст, docx/xlsx/pptx/odt, медиа; всё остальное и папки — только «Показать в проводнике» |
| `.exe .bat .cmd .lnk .ps1 .vbs .js .hta .msi .reg .scr .url .theme .appinstaller …` (≈90 типов) | **блок** |
| `javascript: vbscript: data: file://сервер ms-msdt: search-ms: ms-officecmd: shell:` и любые другие протоколы | **блок** |
| `\\сервер\...`, `//сервер/...`, `\\?\`, `\\.\`, путь через символическую ссылку | **блок** (утечка NTLM, устройства) |
| `CON`, `NUL`, `COM1`…, `файл.md:поток`, `setup.exe.`, `setup.exe%20` | **блок** (устройства, потоки NTFS, маскировка расширения точкой/пробелом в конце) |
| адрес со скрытыми управляющими/bidi-символами | **блок** (Trojan Source, CVE-2021-42574) |

Дополнительно:

- **Настоящий адрес виден до клика** в строке состояния, со значком: `↗` веб, `📄` документ, `📁 (спросит)`, `⛔ заблокировано`.
- Заблокированные ссылки сразу видны в тексте: цвет предупреждения и пунктирное подчёркивание.
- Предупреждение перед открытием, если текст ссылки показывает один сайт, а ведёт на другой (`[https://bank.com](https://evil.com)`, «Войти на bank.com»; невидимые символы и «точки-двойники» `．` `。` перед сравнением убираются), если в адресе есть `user@` перед именем сайта (`https://bank.com@evil.com`) или если в имени сайта не-латинские буквы. В редакторе (Ctrl+клик) сверяется видимый текст ссылки.
- `mailto:` — только адрес и `subject`/`body`/`cc`/`bcc` (без `attach=`), спецсимволы кодируются.
- Незакрытая `<a href>` закрывается на границе абзаца (не превращает документ в одну невидимую ссылку).
- Служебные ссылки `vmd:` (установка/удаление) работают только на встроенной стартовой странице — документ не может их вызвать.

### Картинки (`images.rs`, `net.rs`)

- Те же правила путей, что у ссылок: никаких `\\сервер`, устройств и потоков; принимаются только расширения картинок.
- `data:` — только растровые `image/*` в base64: до 8 МБ на картинку и 32 МБ на документ.
- **Декодирование только безопасными Rust-декодерами** (`png`, `zune-jpeg`, `gif`, `image-webp`, `bmp`, `ico`) с лимитами: до 16384×16384 пикселей, до 256 МБ памяти на картинку, локальный файл до 60 МБ. Ошибка или паника декодера ловится в потоке и не роняет программу.
- `width`/`height` из документа ограничены (≤ 10000), пиксели при перекодировании только уменьшаются по каждой стороне, итог ≤ 16 Мпикс (раньше `height="4000000000"` вызывал выделение терабайт и аварийное завершение).
- Одинаковые картинки грузятся одной задачей; задачи от прошлых отрисовок отменяются.
- В RichEdit передаётся **заново закодированная** нами PNG/JPEG, уменьшенная под ширину колонки. Системные кодеки Windows (WIC) чужие байты не разбирают.
- SVG не поддерживается (это XML с собственной поверхностью атак).
- **Картинки из интернета — только с разрешения**: по умолчанию появляется плашка «Загрузить / Всегда загружать». Настройка `remote_images = ask | always | never` в `settings.ini`.
- Загрузка через WinHTTP: только http/https, **никакой автоматической отправки учётных данных Windows** (`AUTOLOGON_SECURITY_LEVEL_HIGH`), cookies выключены, Referer не отправляется, 25 МБ, тайм-ауты и общий лимит 30 с на картинку.
- Адреса локальной сети запрещены: `localhost`, `10.x`, `192.168.x`, `169.254.x`, `100.64/10`, `fc00::/7`, `fe80::/10`, IPv4 внутри IPv6 (`::ffff:`, `::a.b.c.d`, 6to4 `2002::`, NAT64), однословные имена, `.local`, `.lan`…; нестандартные записи IP (`127.1`, `2130706433`, `0x7f.0.0.1`, `0177.0.0.1`) запрещены; имя сервера заранее разрешается через DNS и проверяется; **автоматические редиректы выключены** — каждый редирект проверяется заново (нельзя увести с публичного адреса на роутер), https→http запрещён, до 5 шагов.

### Процесс и сборка

- `SetDefaultDllDirectories(SYSTEM32)` и `SetDllDirectory("")`: DLL ищутся только в System32, текущая папка исключена. Подложить `msftedit.dll` рядом с `.md` бесполезно.
- Политика процесса `ProcessImageLoadPolicy`: запрет DLL с сетевых путей и с низкой меткой целостности, предпочтение System32.
- **Подмена DLL рядом с exe закрыта.** Статически импортируются только KnownDLLs (kernel32, user32, gdi32, advapi32, combase) и API-sets. `uxtheme`, `dwmapi`, `bcryptprimitives` (не входят в KnownDLLs — Windows искала бы их сначала в папке exe, до старта нашего кода) и WinHTTP/shell32/comdlg32/ole32/oleaut32/ws2_32 загружаются отложенно — уже после `SetDefaultDllDirectories(SYSTEM32)`, только из System32. Важно для установщика, запущенного из «Загрузок» с правами администратора. Проверка: `dumpbin /imports dist\vibe-md-viewer.exe`.
- Сборка с Control Flow Guard, ASLR/DEP (по умолчанию в Rust/MSVC), статический CRT.
- Манифест `asInvoker`: просмотрщик всегда работает с обычными правами. Права администратора (UAC) получает только копия-установщик (`--elevated …`) на время установки/обновления/удаления; окно выбора программы по умолчанию и запуск после обновления — из обычного процесса.
- **Установка «для всех пользователей» — только в `C:\Program Files\vibe-md-viewer`** (`FOLDERID_ProgramFiles`; повышенная копия отклоняет любой другой `--target`). Там все папки выше принадлежат администраторам: обычный пользователь не подменит ни папку, ни путь к ней (переименованием родителя, точкой соединения). Своя папка — только при установке «для себя», без прав администратора. От имени администратора удаляются только папки прямо в Program Files.
- **Установщик копирует сам запущенный образ, а не файл по пути.** Запущенный exe можно переименовать: программа с правами пользователя могла бы, пока повышенная копия ждёт UAC, подложить в «Загрузки» свой файл под именем setup.exe. Повышенная копия находит файл по отображению образа (`K32GetMappedFileNameW`), открывает его, запрещая другим запись и удаление, и сверяет идентификатор файла (`open_own_image`, тест `own_image_is_opened_by_mapping`).
- Путь папки установки с `..` и `.` отклоняется.
- Папка установки «для всех» получает защищённые права как у Program Files (изменять — только SYSTEM и администраторы, владелец — администраторы); чужая непустая папка под установку не берётся; путь проверяется (имя `vibe-md-viewer`, не в `%SystemRoot%`, без `" % !`). Удаление сносит только папку с меткой установщика; `cmd /d /v:off`, `PING.EXE` по полному пути, текущая папка — System32.
- **Переезд установки 0.1.x (vibe-mdViewer → vibe-md-viewer, 0.2.0)** удаляет прежнюю папку от имени повышенной копии. Путь берётся не из командной строки, а из `InstallDir` той же области реестра (для «всех пользователей» — HKLM, писать туда может только администратор); удаляется, только если имя папки — `vibe-mdViewer`, путь проходит те же проверки формы и внутри есть метка установщика и exe программы (`is_our_install_dir`, тест `legacy_install_is_recognized_and_moved`). Чужое имя, папка без метки — не трогаются.
- Каждая оконная процедура обёрнута в `catch_unwind`: непредвиденная ошибка не завершает процесс и не раскручивается через кадры user32. Разбор документа и подсветка тоже под страховкой (при сбое документ показывается как текст).
- Агрессивные политики (запрет динамического кода, запрет расширений) не включены сознательно: они ломают сторонние расширения проводника в диалогах открытия файла и программы переключения раскладки.

### Отказ в обслуживании

- Файл больше 64 МБ не открывается.
- pulldown-cmark линеен на патологических входах; **код самой программы тоже**: поиск голых адресов, токенизатор HTML (тег ≤ 4 КБ, позиция `>` запоминается), декодирование сущностей (`;` ищется в первых 32 байтах), группы RTF (счётчик вместо пересчёта, глубина ≤ 48, HTML-группы ≤ 256).
- Ссылки/якоря/картинки с маркерами — до 2048/1024/2048; адреса длиннее 8 КБ не копируются и не разбираются (мегабайтное определение `[x]: …`, на которое ссылаются тысячи раз, не размножается в памяти).
- Таблицы: ≤ 60 колонок (предел RichEdit — 63), ≤ 60 000 ячеек на документ (дальше «таблица обрезана»); весь RTF ≤ 96 МБ, дальше — сообщение «откройте режим Код».
- Картинки декодируются в фоновых потоках — большой файл не подвешивает окно.
- Подсветка синтаксиса (`highlight.rs`): один проход без регулярных выражений и возвратов; незакрытая строка/комментарий доходит до конца строки или блока; блок больше 256 КБ не подсвечивается. Цвета — только индексы нашей таблицы цветов, текст кода экранируется как и весь остальной (тест `covers_everything_and_is_linear`: 10 000 незакрытых строк и т. п.).
- Тест `pathological_inputs_are_fast_and_balanced` прогоняет ≈25 «бомб» (60 000 скобок, 300 000 `<b>`, 1 000 000 `&`, `<a <a <a…`, мегабайтные определения ссылок, 100 МБ `data:`, таблица 60×6000…): всё ≤ 1 с, RTF сбалансирован, память ограничена.

### Сохранение

- Автосохранение пишет **только в открытый файл** (тот же путь, та же атомарная запись), только если текст в редакторе отличается от сохранённого; стартовая страница и файл без пути не сохраняются. Ошибка записи не повторяется в цикле — сообщение в строке состояния. Выключается `autosave=0`.
- Атомарная запись: временный файл с уникальным именем (`create_new` — подложенный файл или символическая ссылка не перезаписываются) → `ReplaceFileW` (сохраняет атрибуты и права) → при сбое оригинал цел.
- Кодировка и концы строк сохраняются как в исходном файле. Если в ANSI-файл добавлены символы вне кодовой страницы — сохраняется в UTF-8 с сообщением.

## Известные ограничения

- Запущенная копия доверяет локальным файлам, на которые ссылается документ: они **показываются** (картинки) или открываются **после подтверждения**. Информация никуда не отправляется — в программе нет исполняемого кода документа, который мог бы её вынести.
- Пути с символическими ссылками отклоняются при клике и при загрузке картинки. Junction (точки подключения) разрешены — они ведут только на локальные тома.
- Если пользователь сам разрешил картинки из интернета, их серверы узнают IP и время открытия — это предупреждено в плашке.
- **DNS-rebinding** (только после разрешения картинок из интернета): имя проверяется заранее, но WinHTTP разрешает его ещё раз; сервер с TTL=0 теоретически может во второй раз вернуть адрес локальной сети и получить «слепой» GET-запрос. Полное закрытие требует проверки IP при подключении, что ломает работу через корпоративные прокси; риск низкий, оставлен осознанно.
- exe не подписан сертификатом: SmartScreen предупреждает о неизвестном издателе. Подпись — платный сертификат или бесплатная программа для открытых проектов (например, SignPath Foundation) — решение владельца. Подлинность релиза можно проверить по подписи происхождения GitHub: `gh attestation verify <файл> -R SiTiROS/vibe-md-viewer`.
- «Показать в проводнике» открывает папку, на которую указывает документ (после подтверждения). Если там лежит `desktop.ini` со значком на сетевом пути, проводник может обратиться к чужому серверу — это поведение проводника, не программы.
- Установка 0.1.x в своей папке «для всех» при переезде на 0.2.0 не удаляется (от имени администратора удаляются только папки в Program Files) — её можно удалить вручную.

## Независимый аудит (2026-11-18)

Код проверял отдельный ревьюер «с нуля» (статическое чтение, без знания выводов автора). Все подтверждённые находки исправлены и покрыты тестами:

| Находка | Серьёзность | Статус |
| --- | --- | --- |
| Короткие имена 8.3 (`X~1.LIB`) обходили блок опасных типов | высокая | исправлено: длинное имя + белый список |
| RTF-инъекция в редакторе через документ, начинающийся с `{\rtf` | высокая | исправлено: TOM `SetText` (найдено автором, подтверждено самотестом) |
| Подмена DLL рядом с exe (uxtheme/dwmapi/bcryptprimitives) | высокая для установщика | исправлено: отложенная загрузка |

## Независимый аудит 0.2.0 (перед публикацией исходников)

Второй независимый ревьюер, статическое чтение. Исполнение кода из документа и RTF-инъекция не найдены; находки — в установщике и в обработке крайних случаев. Все исправлены, к каждой — тест:

| Находка | Серьёзность | Статус |
| --- | --- | --- |
| Установка «для всех» в свою папку: родитель папки доступен обычному пользователю → подмена exe для всех пользователей, перенаправление удаления от имени администратора | средняя–высокая | исправлено: только Program Files, удаление от имени администратора — только там |
| Повышенная копия копировала exe по пути из «Загрузок» — файл можно подменить, пока ждёт UAC | средняя | исправлено: копия самого образа по дескриптору со сверкой |
| `<img width=1 height=10000>` у картинки 16384×16000: промежуточный буфер масштабирования ≈ 2,6 ГБ → аварийное завершение | средняя | исправлено: ограничение буфера, иначе «миниатюра» |
| Подсветка: тысячи незакрытых `#[` / `${` — квадратичное время, окно «висит» | низкая | исправлено: поиск закрывающей скобки только в строке |
| Автосохранение затирало изменения файла, сделанные другой программой (git pull), и файлы, прочитанные с заменой повреждённых символов | низкая (потеря данных) | исправлено: автосохранение останавливается, Ctrl+S спрашивает |
| GitHub Actions: токен в `.git`, право записи у всего задания сборки, действия по метке, сборка без `--locked` | низкая | исправлено: `persist-credentials: false`, сборка и публикация — разные задания, хеши, `--locked`, подпись происхождения |

## Как проверить

- `cargo test` — юнит-тесты политики ссылок (javascript, протоколы, UNC, устройства, потоки, исполняемые, 8.3, хвостовые точки, bidi, подмена адреса), картинок (огромные размеры), сети (частные адреса, редиректы), экранирования RTF, PUA, HTML, «бомб», установщика (реестр на временной ветке, обновление поверх «запущенного» exe).
- `tests/fixtures/attack.md` — набор атак для ручной проверки: ни одна ссылка не должна сработать, ни одна сетевая картинка не должна загрузиться.
- `scripts/selftest.ps1` — сквозная проверка на живом окне (43 проверки, включая RTF-инъекцию, окно поиска, автосохранение при изменении файла другой программой).
